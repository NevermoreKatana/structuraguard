# ADR 0037: Канонические сериализации значений на границе БД

Статус: принято.

## Решение

JSON не имеет отдельных типов DATE и UUID. Строка с точной записью `YYYY-MM-DD`
может представлять DATE; UUID принимается только в канонической записи,
равной `str(UUID(value))`. Профиль допускает такое сопоставление только по полным
признакам канонической записи. Каждое значение независимо проверяется перед
обращением к БД. Локальные форматы, пробелы, усечение времени, исправление дат
и неявное угадывание формата не допускаются.

Исходные normalized values, provenance и fingerprints остаются неизменными.
На границе БД применяется общая проекция: каноническая строка DATE получает
тот же scalar, что и уже типизированная дата. Эта проекция используется
для CHECK rules, UNIQUE/FK сравнений, mapped_parent, зависимостей исполнения,
параметров read-only lookup и записи. Иначе одна дата могла бы получить
разные ключи или ложный отказ в зависимости от исходного представления.

Проекция не меняет права на запись, SQL, scope, ограничения БД, проверки
обязательности полей или правила транзакции. Неканонические строки остаются
строками и отклоняются штатной проверкой типов/значений; silent fallback нет.
