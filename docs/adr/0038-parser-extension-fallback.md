# ADR-0038: расширение как запасной признак формата

Статус: принят по требованию пользователя от 2026-09-28.

## Причина

Текстовый лог с обрывком первой записи может одновременно подтверждаться LOG
и CSV: запятые внутри JSON выглядят как разделители. Markdown с заголовком и
парами `ключ: значение` может подтверждаться одновременно Markdown и YAML.
Отказ при любом таком совпадении блокирует допустимые источники.

## Решение

1. Сначала выполняются прежние bounded probes и сравнивается content evidence.
   Однозначный сильнейший формат всегда побеждает независимо от расширения.
2. Если сильнейшие кандидаты указывают разные форматы, среди всех успешно
   проверенных кандидатов ищется совпадение расширения. Один совпавший формат
   разрешает конфликт. TXT может быть слабее структурных кандидатов и при этом
   сохранять весь исходный текст. Несколько adapters одного формата выбираются
   прежним детерминированным ranking.
3. LOG и Markdown без узнаваемой структуры допускают кандидата по расширению
   только после успешного декодирования и проверки текстового содержимого.
   Они сообщают CONTENT_MEDIA_TYPE, а не выдуманный INTERNAL_STRUCTURE.
4. Запасной выбор виден в `ProbeResult.warnings`: `PARSER_EXTENSION_FALLBACK`.
   Нет подходящего расширения или оно указывает несколько форматов — остаётся
   `PARSER_FORMAT_CONFLICT`. Unsupported parser не становится eligible.

Это уточняет прежний запрет разрешения format conflict из плана M03.
FR-002 сохраняется: одного имени файла недостаточно; положительная проверка
содержимого обязательна. Обработка расширений использует существующие aliases
adapters и не зависит от регистра.

## Границы и совместимость

Ошибки декодирования, security limits, cancellation, ошибки probe и parsing
не перехватываются ради fallback. Бинарный файл не превращается в текстовый
переименованием. Нет дополнительного чтения, LLM-вызовов или внешнего сервиса.
Парсер сохраняет строки и provenance; неполные записи не отбрасываются.
Выбор формата не гарантирует, что из повреждённой записи можно получить все
обязательные поля целевой таблицы. Проверки дальнейших этапов сохраняются.

Публичные DTO не меняются. В отличие от прежнего поведения, простой текст в
`.log`/`.md` и известная неоднозначность с подходящим расширением проходят с
явным warning. При неверном расширении неоднозначный текст может получить
нежелательную интерпретацию; причина выбора доступна вызывающей стороне.
