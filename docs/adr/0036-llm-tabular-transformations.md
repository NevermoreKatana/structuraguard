# ADR 0036: Семантический план преобразования перед ingest

Статус: принято.

## Причина

Сопоставление по профилям не решает преобразование одного исходного поля в
несколько целевых. Исходная закрытая грамматика MappingPlan связывает одно
normalized field с одной колонкой. Пользователь требует поручить модели
интерпретацию значений и схемы: например, «Индекс» → postal_code, составное
«Фамилия_имя» → отдельные колонки имени и фамилии.

## Решение

Публичный TabularImportPlanner составляет предварительный copy/split план.
LLM получает имена, примеры строк и все разрешённые изменяемые колонки выбранной
таблицы, включая типы, NULL, ключи и комментарии. Лексический фильтр отсутствует.
Модель определяет смысл, порядок частей и уверенность; SDK связывает только
выданные IDs, проверяет покрытие и исполняет операции для всего снимка.

Поддержаны перенос значения и разделение по whitespace/буквальному разделителю.
Все части должны быть использованы; неизвестные выражения, потеря частей,
коллизии, недостаточная уверенность и несовместимые строки требуют проверки.
План связан с fingerprints данных, каталога и scope. Сохраняются lineage и
локальные примеры до/после. SQL и произвольный код от модели не исполняются.

Реальные bounded samples доступны только при явной LOCAL_ONLY policy. SDK
проверяет secrets, injection и exact approval запроса; локальность не снимает
resource limits. Семантическая уверенность модели является эвристикой, поэтому
обычные ограничения типов/БД, staging, dry-run и транзакция остаются обязательны.

## Совместимость и границы

Существующий MappingPlan, M11 и loader не изменяются. Результат предварительного
плана передаётся штатному ingest как JSON, а приложение сохраняет исходный план
и provenance вместе с отчётом. Перед записью проверяется актуальность схемы.
Первый вариант ограничен одной существующей таблицей и строками/NULL. Непонятные
составные поля, произвольные вычисления и межтабличные преобразования не
маскируются автоматическими эвристиками.

Альтернатива — включить преобразования непосредственно в MappingPlan — потребовала
бы одновременного изменения его wire-версии, validation и loader. Отдельная
подготовка сохраняет эти проверенные границы и остаётся частью публичного SDK.
