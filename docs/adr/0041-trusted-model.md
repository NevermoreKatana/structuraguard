# ADR 0041 — Явный флаг доверенной модели

Статус: принято по явному подтверждению пользователя от 2026-09-29.

Сервер пользователя с GPU может находиться на другой машине. Сетевой адрес
не определяет принадлежность сервера. В `ProviderCapabilities` добавляется
`trusted_model: StrictBool = False`: host подтверждает, что сервер контролируется
владельцем данных и ему разрешено обрабатывать любые файлы, включая RESTRICTED.

`execution_environment` сохраняет физическую декларацию local/cloud. Предикат
`controlled_deployment` объединяет LOCAL и явно доверенный CLOUD. Неизвестное или
отключённое окружение не становится допустимым после включения флага. `LOCAL_ONLY`
и `PRIVACY_FIRST` учитывают контролируемый контур; классификация данных остаётся
прежней. Provider, router, semantic parsing и pipeline проверяют одно правило.

Флаг включён в capabilities fingerprint и потому связан с выбранным deployment
и маршрутом. Изменение флага требует новой policy/approval; отзыв запрещает reuse
старой привязки. По умолчанию сериализация capabilities и поведение прежние.

TabularImportPlanner для FIXED с одной доверенной моделью не требует разрешения
на каждый файл. Выборка остаётся ограниченной, каждый payload проходит scanner,
а план — schema, confidence, scope и all-row validation. Флаг не доверяет ответам
LLM, не включает tools/SQL, не отключает budgets, injection checks или запрет
передачи credentials. Недоверенная внешняя модель сохраняет прежние ограничения.

Песочница хранит флаг вместе с зашифрованным подключением, показывает checkbox и
разрешает отдельное явное обновление без выдачи URL/API key. Старые подключения
остаются недоверенными; сервер пользователя помечается по его прямому указанию.
