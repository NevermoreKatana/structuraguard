# Quality gates

## На каждой связной правке

1. Тест, фиксирующий требование или дефект.
2. Минимальная реализация.
3. Форматирование и lint затронутых файлов.
4. Узкие тесты изменённого модуля.
5. Проверка типов затронутого пакета, если поддерживается.

## Перед завершением задачи

- Проверить `git diff --check`.
- Убедиться, что нет секретов, debug prints, временных файлов и закомментированного кода.
- Проверить публичный API, обратную совместимость и документацию.
- Запустить доступные `make lint`, `make typecheck`, `make test`.
- Для БД/парсеров/ИБ дополнительно запустить integration/security suites.
- Не писать «готово», пока команды не завершились успешно либо их невозможность не объяснена конкретно.

## Запрещённые способы получить зелёный CI

- Удаление или ослабление теста без изменения требования.
- `# type: ignore`, `noqa`, skip и broad exception без локального обоснования.
- Исключение файлов из lint/typecheck.
- Мокирование проверяемой логики вместо внешней границы.
- Понижение security defaults.
