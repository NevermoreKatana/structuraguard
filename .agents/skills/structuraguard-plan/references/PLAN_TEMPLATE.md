# Шаблон плана

## Цель

Одно проверяемое предложение.

## Критерии приёмки

- Наблюдаемое поведение.
- Ошибочные и граничные случаи.
- Ограничения безопасности и совместимости.

## Затронутые контракты

- Public API / DTO / protocol.
- Persistence / schema / wire format.

## Шаги

1. `path/to/test.py` — тест, который сначала воспроизводит требование или дефект.
2. `path/to/module.py` — минимальная реализация.
3. Документация или ADR только при изменении контракта.
4. Команды проверки.

## Риски

Только реальные риски: data loss, schema drift, compatibility, security, performance.
