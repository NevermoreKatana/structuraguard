# План изменения

## Вход

Цель, критерии приёмки, ограничения и текущий milestone.

## Workflow

1. Прочитай `AGENTS.md`, `docs/codex/PROJECT_CONTEXT.md` и строку текущей работы в `docs/codex/SPEC_INDEX.md`.
2. Извлеки только нужные разделы ТЗ через `scripts/extract_spec_sections.py`.
3. Найди существующие contracts, соседнюю реализацию и тесты. Не проектируй параллельный механизм без проверки текущего.
4. Сформулируй наблюдаемое поведение до и после изменения.
5. Проверь архитектурные границы, совместимость API, миграции данных и trust boundaries.
6. Разбей работу на вертикальные шаги. Каждый шаг должен содержать конкретные файлы, поведение, тест и команду проверки.
7. Отдели обязательный scope от последующих улучшений. Соблюдай YAGNI.
8. Для спорного решения запиши варианты, trade-offs и выбранный вариант; ADR нужен только для долгоживущего архитектурного решения.

## Выход

Краткий исполнимый план без повторения всего ТЗ. Не пиши код в план и не вставляй большие шаблоны.

Используй [шаблон плана](references/PLAN_TEMPLATE.md), когда план сохраняется в файл.
