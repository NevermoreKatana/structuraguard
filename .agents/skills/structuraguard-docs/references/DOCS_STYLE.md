# Стиль документации

- Короткие предложения и предметные заголовки.
- Один термин — одно написание.
- Сначала пример, затем детали и ограничения.
- Не использовать рекламные слова: «идеальный», «безошибочный», «любой без ограничений».
- Явно различать MUST, SHOULD и optional.
- Ошибки показывать вместе с machine-readable code.
- В примерах DSN/API keys заменять безопасными placeholders.
- Диаграмма должна соответствовать текущим package boundaries.
